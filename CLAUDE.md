# GetBalance AI — мобильное приложение (Flutter)

Устройство кода, слои, сервисы и модели — в `ARCHITECTURE.md` (большой, читать нужный раздел). Запуск и окружения — `README.md`. Бэкенд — соседний репозиторий `../getbalanceai_api`, свои `CLAUDE.md` там.

## Код
* **Переиспользовать готовое, не хардкодить.** Перед новым виджетом или сервисом искать аналог в `lib/widgets`, `lib/utils`, `lib/services`: кнопки `SheetPrimaryButton`/`SheetOutlinedButton`, шторки `AppSheet`/`SheetHandle`/`KeyboardInsetPadding`, переносы `WholeWordsText`/`OneLineLabel`, чипы категорий, форматтеры сумм, цвета `AppColors`. Общий кусок выносить в переиспользуемый компонент, а не копировать. Визуал пользователь смотрит сам и даёт косметические правки — код должен позволять внести их в одном месте.
* **Мёртвый код удалять сразу.** Если правка оставляет методы, модели или ключи l10n без вызовов в `lib/`, удалять их каскадом в той же ветке вместе с тестами удалённого кода; живые проверки переносить. Оставлять тестовые точки доступа (`ApiService.auth/sync/...`) и API, через который тесты проверяют живую логику (`SyncService.syncBackendDataToLocal`). Пункты, у которых в чек-листе свой блок, не трогать раньше времени.
* **Без иконок на кнопках действий и в сообщениях** (тосты, алерты, шторки). Иконки — только у категорий и у пунктов меню в «Профиле».
* **Без дублирующих элементов.** Прежде чем добавить кнопку по пункту чек-листа, проверить, нет ли уже механизма (pull-to-refresh, автоповтор) и что говорят тексты экрана в ARB. Например, «Повторить» не нужен там, где текст говорит «потяните экран вниз».
* Тексты — через l10n (`lib/l10n/app_*.arb`, все языки — сейчас ru и en), не строками в коде. Длинные значения проверять на переносы при крупном шрифте.
* **Языки**: всё, что видит пользователь, — на языке его интерфейса: тексты приложения, юридические страницы, промпт и данные для ИИ (чтобы и ответ был на этом языке), сообщения об ошибках (приложение берёт их из l10n по коду, текст сервера не показывает). Комментарии, внутренняя документация (включая Swagger), исключения, логи, Grafana и Prometheus — на русском.
* **Язык по умолчанию — английский**: если язык системы или локаль не поддерживаются — `en`, не `ru` (и в приложении, и в ответах бэкенда).
* **Приложение ещё не выпущено**: обратную совместимость со старыми версиями приложения и их данными (миграции настроек и локальной базы, фильтры «на случай старого клиента») не делать, пока пользователь не скажет обратное. На тестовом телефоне при несовместимых изменениях — чистая установка.

## UX — только по запросу
Навигацию, точки входа, онбординг, раскладку и «умную» автоматику (автоопределение региона, валюты и т.п.) не менять сверх явно согласованного. Пункты ревью — предложения, а не план: сначала коротко предложить и дождаться «да». Если пользователь сказал «делай», не выбрав вариант раскладки, — сначала показать вариант (скриншот, превью). Плитки «Доход / Расход» на «Балансе» — квадратные, не менять.

## Проверки
Запускаю сам и прикладываю фактические результаты в конце задачи:
```bash
fvm dart format lib test
fvm flutter analyze
fvm flutter test
fvm flutter gen-l10n                                              # после правки app_*.arb
fvm dart run build_runner build --delete-conflicting-outputs      # после правки моделей ObjectBox
```
Pre-commit хук (`.githooks/pre-commit`) повторяет format и analyze.

Проверка на телефоне и установка release — скилл `getbalance-device-check`.
